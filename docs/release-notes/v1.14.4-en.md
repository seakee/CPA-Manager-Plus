## Overview

v1.14.4 is a maintenance patch after v1.14.3 and remains within the frozen 1.x maintenance boundary. It fixes three confirmed issues: xAI/Grok health inspection failing with HTTP 426 because CPAMP still identified itself as an obsolete Grok CLI client, Claude model discovery and connectivity tests using the wrong authentication header for custom Base URLs, and analytics summary comparison returning HTTP 500 when historical raw usage had been removed through the supported cleanup flow and historical pricing coverage could no longer be proven.

xAI requests now use a Grok client identity compatible with the current CPA behavior. Claude probe authentication follows the CPA v7.3.4+ runtime rules: Anthropic first-party API keys continue to use `x-api-key`, while custom compatible endpoints can use `Authorization: Bearer` according to the effective configuration. Usage analytics now degrades only the unprovable `SummaryComparison` when historical comparison coverage cannot be established; it does not fabricate cost data, and primary queries, genuine SQLite failures, and recovery errors remain fail-closed.

## Highlights

### Fixes

- Update the xAI/Grok health-inspection Grok CLI client identity and keep billing / inference User-Agent values synchronized, preventing HTTP 426 failures caused solely by the obsolete `0.2.101` identity falling below the upstream minimum-version gate. (Web / xAI compatibility)
- Fix Claude model-discovery and connectivity-test authentication to match CPA v7.3.4+ runtime behavior. Anthropic first-party endpoints keep `x-api-key`; custom Base URLs can correctly use Bearer authentication, and explicit custom-header overrides remain authoritative. (Web / Claude compatibility)
- Tighten Claude probe diagnostics so they report only the presence of effective authentication headers and never expose API-key, token, or custom authentication values. (Web / Security)
- Fix HTTP 500 responses when `SummaryComparison` is requested after supported historical raw-usage cleanup and historical pricing coverage cannot be proven. The service now omits only the unprovable comparison field and reports the corresponding coverage limitation. (Manager Server)
- Keep primary-window queries, genuine SQLite query failures, recovery-query errors, and pricing-coverage integrity checks fail-closed so incomplete historical data is never used to fabricate costs. (Manager Server / Data integrity)

## Upgrade Notes

- No database migration or CPAMP configuration change is required.
- xAI/Grok users do not need to re-authenticate; this release only updates the client identity used by health-inspection requests.
- Existing Anthropic first-party API-key configurations require no changes. Custom Claude-compatible Base URLs automatically use the effective authentication mode derived from the existing configuration.
- Instances that have already removed historical raw usage through the supported cleanup flow will no longer fail analytics solely because an older comparison window cannot prove pricing coverage. The current-window summary remains available; only the unprovable historical comparison is omitted.
- The full Muse / Meta compatibility baseline remains **CPA v7.3.4+**; this release does not raise the minimum CPA compatibility baseline.
