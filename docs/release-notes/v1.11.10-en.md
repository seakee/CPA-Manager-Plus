## Overview

This release focuses on more accurate local cost estimates, safer authentication-file operations, and clearer realtime monitoring. Model-price synchronization now prefers first-party canonical metadata from models.dev and applies context tiers and Fast/Priority service tiers across Dashboard, Monitoring, and account history. Authentication-file mutations are fenced by canonical credential identity, while the realtime request table uses a single total-latency TPS definition.

## Highlights

### Features

- Prefer canonical model metadata from the models.dev catalog, followed by LiteLLM and OpenRouter fallbacks. Only unique strong identity matches are saved automatically, and last-known-good prices remain available when every source fails (`manager-server/model-pricing`).
- Parse, validate, and persist models.dev context tiers and explicit Fast/Priority rates, applying them through durable pricing rollups to Dashboard, Monitoring, account history, and frontend usage costs (`manager-server/usage-pricing`, `web/usage`).
- Display synchronized context tiers and service-tier rules as read-only data on Model Prices, preserve ambiguous candidates by source, and warn before a manual base-price save clears synchronized advanced rules (`web/model-prices`).

### Fixes

- Fence authentication-file status changes, deletion, quota-cooldown recovery, and inspection operations by canonical credential identity while serializing mutations for shared physical files. Stale or ambiguous targets now fail closed instead of affecting another credential (`manager-server/auth-files`, `web/auth-files`).
- Use total request latency for the realtime table's single TPS value and improve compact column alignment, token details, failure diagnostics, and tooltip readability (`web/monitoring`).

### Docs

- Expand the English and Chinese model-price guides with source priority, synchronization fallback, context-tier and Fast/Priority semantics, and manual-override boundaries (`docs/model-prices`).

## Upgrade Notes

- Manager Server automatically migrates model-price rules, pricing-rollup state, and credential-identity records on startup. No manual database or configuration migration is required.
- Older binaries are not guaranteed to support the migrated credential ownership and cooldown uniqueness structure. Back up the SQLite files and `data.key` before upgrading, and restore that backup for an exact rollback to v1.11.9.
- Accurate Fast/Priority and context-tier estimates depend on service-tier, context, and cache metadata in CPA usage events. Missing metadata uses compatibility fallbacks, and provider billing remains authoritative.
- Model-price synchronization remains user-triggered. Existing prices change only after synchronization, candidate confirmation, or manual editing; CPA routing and upstream billing behavior are unchanged.
