## Overview

v1.14.8 是 v1.14.7 之后的 1.x 维护版本，整合四项已经合并的前端修复：后台刷新数据连续性（#1001）、实时监控来源识别（#1014）、配额窗口显示（#1020），以及 xAI OAuth 订阅计划与可观察配额识别（#1006）。

本次不包含 v2 架构改造，不修改 Manager Server、CPA 管理 API、数据库 Schema、凭证格式或配置格式。没有新增用户配置项或迁移步骤。

## Fixes

- **后台刷新连续性（#1001）**：凭证历史、配额使用量、Usage Analytics 和模型价格表在相同连接及数据作用域内刷新时保留已加载的数据，避免请求进行中或暂时失败时闪烁、清空或错误显示空态。
- 对于替换的凭证，历史及配额使用量以当前凭证身份隔离；未变更的其他凭证仍保留其有效快照。滚动时间范围跨日及筛选条件变化时，旧数据按作用域正常失效。
- **实时监控来源（#1014，修复 #1013）**：不同提供商共享 API Key 或 Host 序号时，结合事件提供商解析来源，保留原本配置的上游标签；提供商不明或同提供商内仍有歧义时，不猜测具体来源。不会展示原始密钥。
- **配额窗口展示（#1020）**：Antigravity 的卡片与表格最多显示五个主要配额窗口，包括独立的 Gemini 4 Argon 分组。明确区分已确认的空模型用量和用量未知、快照过期、范围不完整或获取失败等状态。
- **xAI OAuth 订阅（#1006，修复 #1005）**：当 CPA 凭证文件缺少订阅计划时，通过 CPA 既有 `api-call` 入口后台查询订阅信息；已确认的 SuperGrok Heavy 计划可正确显示，无法确认订阅时仍展示实际获取到的配额。
- xAI 配额展示与健康判断分离：只有可信的最新订阅证据才能确认计划与可用性；旧结果不会跨连接或凭证替换复用。订阅查询仅在刷新后触发，并采用去重的低优先级串行查询，不新增定时轮询。

## Upgrade Notes

- **从 v1.14.7 正常升级并重启即可。** 没有数据库迁移、配置修改或凭证重建要求；`migration_required` 为 `false`。
- #1006 的订阅计划补充依赖 CPA 已有的 `api-call` 能力及上游订阅接口。若上游接口不可用，订阅计划可能保持未知；已有配额显示不会因此被隐藏，也不会仅凭旧计划宣称可用。
- #1001 仅保留相同作用域的最后一次可信数据；连接、凭证或筛选条件变更后仍会失效，避免跨账号混用。
- 完整 Muse / Meta 功能的 CPA 最低兼容基线仍为 **v7.3.4+**，本版本不提高该要求。
- v1.14.7 关于已有非空数据库延迟分析覆盖索引的离线维护说明继续适用；本版本没有新增索引或维护命令。
