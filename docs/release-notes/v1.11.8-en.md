## Overview

This release strengthens the Manager Server credential-health inspection lifecycle. Recoverable SQLite leases prevent duplicate inspections across instances, users can cancel active runs, and service restarts or transient SQLite write locks no longer leave runs without a terminal state.

## Highlights

### Fixes

- Use a database lease to keep credential-health inspection single-instance across Manager Server instances, preventing duplicate inspection or concurrent processing of the same credentials (`manager-server/codexinspection`).
- Allow active credential-health inspections to be stopped from the Monitoring panel. The UI shows cancelling, cancelled, and interrupted states while retaining completed results and logs (`web/monitoring`).
- Recover expired inspection leases at startup and wait for active inspections to persist a terminal state during shutdown; transient SQLite write locks no longer block the entire inspection lifecycle (`manager-server/codexinspection`).
- Make inspection polling, start, and cancellation follow the latest action so stale responses cannot show a cancelled run as still active (`web/monitoring`).

## Upgrade Notes

- Manager Server automatically creates the inspection lease table and expiry index at startup; existing `usage.sqlite` files need no manual migration.
- An inspection active during service shutdown ends as interrupted. Start it again from Monitoring after the upgrade or restart.
- This release adds no inspection configuration settings.
