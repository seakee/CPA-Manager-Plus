## Overview

v1.14.4 是 v1.14.3 之后的维护补丁版本，继续遵守 1.x 功能冻结边界，集中修复三个已确认问题：xAI/Grok 健康巡检因过期 Grok CLI 客户端标识触发 HTTP 426、Claude 自定义 Base URL 在模型获取与连通性检测时使用了错误的鉴权头，以及历史原始用量已经按支持流程清理后，趋势摘要对比可能因无法证明历史定价覆盖而返回 HTTP 500。

xAI 请求现在统一使用与当前 CPA 兼容的 Grok 客户端版本标识；Claude 探测鉴权与 CPA v7.3.4+ 运行时规则保持一致，Anthropic 官方 API Key 继续使用 `x-api-key`，自定义兼容端点可按实际配置使用 `Authorization: Bearer`；用量分析则在仅有历史对比区间无法证明定价覆盖时降级省略 `SummaryComparison`，不会伪造成本数据，同时主查询、SQLite 错误与真实恢复错误仍保持 fail-closed。

## Highlights

### Fixes

- 更新 xAI/Grok 健康巡检使用的 Grok CLI 客户端版本标识，并统一 billing / inference 请求的 User-Agent，避免因旧版 `0.2.101` 低于上游最低版本要求而触发 HTTP 426。（Web / xAI compatibility）
- 修复 Claude 模型发现与连通性测试的鉴权构造，使其与 CPA v7.3.4+ 运行时规则一致；Anthropic 官方端点继续使用 `x-api-key`，自定义 Base URL 可正确使用 Bearer 鉴权，且自定义 Header 覆盖规则保持生效。（Web / Claude compatibility）
- 收紧 Claude 探测诊断信息，只报告有效鉴权头是否存在，不输出 API Key、Token 或自定义鉴权值。（Web / Security）
- 修复历史原始用量已清理时，请求 `SummaryComparison` 可能因无法证明历史定价覆盖而返回 HTTP 500 的问题；此场景现在仅省略无法证明的对比字段，并返回对应 coverage limitation。（Manager Server）
- 保持主时间窗口、真实 SQLite 查询错误、恢复查询错误与覆盖完整性要求 fail-closed，避免用不完整历史数据推导或伪造成本。（Manager Server / Data integrity）

## Upgrade Notes

- 无需数据库迁移，也无需修改现有 CPAMP 配置。
- xAI/Grok 用户升级后无需重新登录；本版本仅更新健康巡检请求使用的客户端身份标识。
- Claude 官方 Anthropic API Key 配置无需调整。使用自定义 Claude-compatible Base URL 的实例会自动按现有配置重新选择有效鉴权方式。
- 历史原始用量已按支持流程清理的实例，在无法证明历史对比区间定价覆盖时将不再返回错误；当前时间窗口摘要保持正常，无法证明的历史对比会被省略。
- 完整 Muse / Meta 功能的 CPA 基线继续为 **v7.3.4+**；本版本没有提高最低兼容基线。
