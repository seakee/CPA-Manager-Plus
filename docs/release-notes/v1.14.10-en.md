## Overview

v1.14.10 improves the 1.x credential workspace and addresses model-exclusion precedence, historical pricing reads, plugin configuration defaults, and in-page URL synchronization. Manager Server gains narrowly scoped read-only forwarding for CPA v8 API-key groups. No v2 architecture changes are included.

## Changes

### Credentials and UI

- **Pinned credentials (#1098, #1102):** Pin watched credentials in table or card view. Matching pins appear first in pin order while existing filters and the order of unpinned results remain in effect. A lightweight inline pin beside the account name avoids overlapping provider logos. Pins are browser-local and unavailable in selection mode.
- **Effective model exclusions (#1080):** Model badges, counts, actions, and editing guidance now reflect the CPA OAuth precedence for the detected version. CPA v6.10.8–v8.0.32 combines global and credential exclusions; v8.0.33+ makes a non-empty credential list override global exclusions, while an empty list inherits them. Editing avoids silently re-enabling globally excluded models, and unknown CPA versions receive conservative edit restrictions.
- **Same-page URL state (#1099):** Fix navigation updates that changed only search parameters or fragments. Credential filters, search, sorting, layout, and detail state stay synchronized with reloads, browser history, and shared links. Late URL echoes no longer overwrite newer search input.
- **Plugin configuration defaults (#1073):** When a saved field is absent, show the typed default declared by CPA without writing that default during unrelated saves. Explicit stored values such as false, 0, empty string, and null take precedence. Older CPA versions that do not expose defaults retain the prior behavior.

### Manager Server and data reads

- **Historical pricing recovery (#1083):** Recover incomplete pricing reads from intact raw usage events when monitoring projection rows are missing or stale. This avoids some historical analytics and account-cost failures; genuinely missing historical data remains unrecoverable and is never synthesized. No price, schema, or stored-data migration.
- **Read-only CPA v8 API-key groups (#1097):** Manager Server now forwards only authenticated-admin `GET /v8/management/config/api-keys` requests and subpaths so plugin pages can view group names and key identifiers. Writes, other v8 management paths, and unsafe escaped paths remain blocked; CPA Panel mode is unchanged.

### Maintenance

- **Security tooling (#1093):** Bump the development-only locked Zod dependency to resolve an audit advisory; no runtime application behavior change.
- **Dependency update policy (#1070):** Disable routine Dependabot version-update PRs in favor of deliberate development and targeted security updates; no product runtime change.

## Upgrade Notes

- Upgrade normally from v1.14.9 and restart. There are no database migrations, credential recreations, or configuration-format changes.
- Pins are stored only in the current browser, are not synchronized between devices, and do not bypass filters. Renaming an auth file or changing its identity may leave a stale pin unmatched.
- The running CPA version determines OAuth exclusion precedence. Pay particular attention to non-empty credential-level lists on v8.0.33+; CPAMP now reflects upstream behavior rather than changing it.
- The new read-only group view requires CPA with the v8 endpoint. If Manager Server is behind a shared-domain reverse proxy, use the matching route in the [reverse-proxy guide](https://github.com/seakee/CPA-Manager-Plus/blob/v1.14.10/apps/docs/en/deployment/reverse-proxy.md). It remains admin-only.
- The overall minimum CPA compatibility baseline for full Muse / Meta features remains **v7.3.4+**.
- The merged fixes and current dev head passed their respective tests and required CI checks; publication readiness remains subject to the Release Dry Run and release workflow.
