## Overview

这是 v1.12.0 的第三个 beta 版本，聚焦 Accounts 额度周期一致性、兼容用量导出的 SQLite 读取韧性，以及监控、日志和系统信息的可发现性。额度周期在提前或计划重置、深链加载和详情抽屉重开场景下保持正确；慢速兼容用量下载不再长期占用 SQLite 读取器；前端统一费用精度并整理日志、插件和系统入口。

## Highlights

### Features

- Monitoring、Dashboard、Usage Analytics 与 Accounts 的 USD 费用统一显示三位小数；存储值和计算逻辑不变（`web/usage`）。
- 日志入口默认可见，请求日志开关移入可视化配置，并移除 Dashboard 的隐藏解锁手势；直接日志访问继续可用（`web/logs`、`web/config`）。
- 插件被配置为明确禁用时隐藏插件管理导航，同时对缺失插件能力字段的旧环境保持兼容（`web/plugins`）。
- System 信息将服务端版本和主程序仓库改为内核术语，并将教程入口指向 CPAMP 在线文档（`web/system`）。

### Fixes

- Manager Server 仅使用可靠的精确或推导边界确认计划或提前额度重置，并避免临时零用量或未知边界错误拆分当前周期（`manager-server/quota`）。
- Accounts 在额度周期激活、计划滚动和提前重置后保留规范化的当前与上一周期用量；周期标签使用计划边界，而聚合仍使用实际观察区间（`web/accounts`、`manager-server/quota`）。
- Accounts 在手动额度刷新、同一凭证详情抽屉重开及深链凭证异步解析后重新加载额度用量，避免空白或陈旧详情（`web/accounts`）。

### Performance

- 兼容用量接口在释放 SQLite 读取器后分批加载详情，慢速客户端不再阻塞 WAL checkpoint；返回结构、排序和 JSONL 导出路径保持不变（`manager-server/usage`）。
- 为额度周期证据查询增加非破坏性 SQLite 索引，使历史快照增长时的生命周期归一化保持有界（`manager-server/sqlite`）。

### Chore

- GitHub Linguist 不再把 `apps/web` 计入主要语言统计，使仓库元数据以 Go 应用为主；构建和运行时不受影响（`repo`）。

## Upgrade Notes

- 这是预发布版本。稳定 Docker 标签和 `latest` 不会更新，请显式使用 `v1.12.0-beta3` 对应的镜像或发布资产。
- 当 `GET /v0/management/usage` 的配置上限超过 50,000 条时，将返回最新 50,000 条；`/v0/management/usage/export` 仍遵循原配置上限。
- Manager Server 会自动添加非破坏性的额度周期查询索引，无需手工迁移或重写数据。
- 额度周期持久化修复适用于使用 Manager Server 存储的部署；CPA Panel 直接模式的既有能力边界不变。
