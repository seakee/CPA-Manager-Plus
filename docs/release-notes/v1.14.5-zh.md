## Overview

v1.14.5 是 v1.14.4 之后的维护补丁版本，继续遵守 1.x 功能冻结边界，集中修复两个已确认问题：Codex 已知的重置次数可能在额度刷新后被低置信度的零值覆盖、消费重置后由 CPAMP 自动禁用的凭证可能无法及时恢复，以及 OpenAI-compatible 上游即使本身不需要 API Key，也会被 CPAMP 的保存、测试和模型发现流程要求填写占位密钥。

Codex 重置状态现在按证据可信度合并：已有正向证据时，只有专用重置详情明确返回空库存才能清除已知次数；详情请求失败或超时时保留已知状态并标记为陈旧。消费重置后，Manager 可在一次性额度验证成功后尝试恢复精确匹配的 CPAMP 自有冷却状态，并继续保护手动禁用或预先禁用的凭证。整个修复不引入周期轮询、后台重置队列或新的定时器。

OpenAI-compatible 提供商现在可以真正以无密钥方式保存、重新打开、测试、发现模型并执行健康检查。CPAMP 不再构造空的 Bearer 鉴权，也不会为匿名请求生成虚假 Token；当 CPA 无法为无密钥流量提供按 Key 用量统计时，界面会明确显示统计不可用或部分可用，而不是伪造零请求。

## Highlights

### Fixes

- 修复 Codex 重置次数在额度刷新后消失或长期停留在错误值的问题：已有正向重置证据时，count-only / usage summary 的零值不再具有清除权限；只有专用详情明确返回空库存才会清除已知重置。（Web / Codex quota）
- 专用重置详情失败或超时时保留最近一次可信的重置次数与详情并标记为陈旧，避免一次瞬时失败删除仍有效的用户状态；持久化额度快照采用同一证据规则。（Web / Data consistency）
- 在消费 banked reset 后复用一次性额度刷新进行验证；验证恢复后，Manager 可请求提前恢复精确匹配、由 CPAMP 管理的 Codex quota cooldown，并继续拒绝手动禁用、预先禁用或归属不明确的凭证。（Web / Manager Server）
- 明确保持事件驱动：没有新增 provider polling、后台 reset-credit queue、周期任务或定时器。（Web / Manager Server）
- 支持无需 API Key 的 OpenAI-compatible 提供商保存与编辑，并正确映射为空的 `api-key-entries` 或带代理 / 权重等 CPA 支持配置的显式无密钥条目。（Web / OpenAI compatibility）
- 无密钥连通性测试、模型发现与健康检查不再发送空 `Authorization: Bearer`，同时保留用户自定义 Header、每条目代理设置与已有 CPA `auth-index` 路由语义；编辑真实 API Key 时会使旧的瞬时 `auth-index` 失效。（Web / Authentication）
- 当 keyed 与 keyless 条目混合存在时，模型发现优先使用真实 API Key；仅在没有真实 Key 时回退到已配置的无密钥条目。（Web / Model discovery）
- CPA 无法统计无密钥流量时，CPAMP 将该统计标记为 unavailable；混合 keyed / keyless 提供商标记为 partial，并在排序和详情中保留覆盖信息，不再把缺失统计解释为零流量。（Web / Usage integrity）
- `Keys Count` 仅统计真实非空 API Key；无密钥路由在健康检查和详情中明确标识。（Web / Provider UI）

## Upgrade Notes

- 无需数据库迁移，也无需修改现有 CPAMP 配置。
- 现有使用 API Key 的 OpenAI-compatible 提供商保持原行为；无密钥支持只对 OpenAI-compatible 提供商开放，不扩展到其他 Provider 类型。
- 无密钥请求不会自动添加占位 API Key 或空 Bearer 鉴权。用户已配置的自定义 Header 和每条目代理设置继续生效。
- Codex 重置状态修复不增加周期轮询。单账号手动刷新仍是事件驱动，批量 / 列表刷新不会启动后台 reset-credit 刷新队列。
- Manager-backed 的提前恢复仅作用于能够证明由 CPAMP 管理的精确 cooldown；没有 Manager 或无法证明归属时会 fail closed，并保留部分成功语义。
- 完整 Muse / Meta 功能的 CPA 基线继续为 **v7.3.4+**；本版本没有提高最低兼容基线。
