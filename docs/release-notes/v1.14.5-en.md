## Overview

v1.14.5 is a maintenance patch after v1.14.4 and remains within the frozen 1.x maintenance boundary. It fixes two confirmed areas: known Codex reset-credit counts could be overwritten by lower-confidence zero observations during quota refresh and a CPAMP auto-disabled credential could remain disabled after consuming a banked reset; separately, OpenAI-compatible upstreams that do not require an API key were still blocked by CPAMP save, test, and model-discovery flows.

Codex reset state now reconciles observations by evidence authority. When positive reset-credit evidence is already known, only a dedicated reset-credit detail response with an explicit empty inventory may clear it; detail failures and timeouts preserve the last trusted state and mark it stale. After a banked reset is consumed, Manager can attempt one-shot recovery of an exactly matched CPAMP-owned cooldown after quota health is verified, while manual or pre-disabled credentials remain protected. No periodic provider polling, background reset-credit queue, or new timer is introduced.

OpenAI-compatible providers can now be saved, reopened, tested, queried for models, and health-checked without an API key when the upstream supports anonymous access. CPAMP no longer injects an empty Bearer header or synthesizes a token for anonymous requests. When CPA cannot provide per-key usage accounting for keyless traffic, CPAMP reports statistics as unavailable or partial instead of fabricating zero traffic.

## Highlights

### Fixes

- Fix Codex reset-credit counts disappearing or remaining incorrect after quota refresh. When positive reset evidence already exists, count-only or usage-summary zero values are no longer authoritative; only an explicit empty inventory from the dedicated reset-credit detail path can clear the known state. (Web / Codex quota)
- Preserve the last trusted reset count and detail when the dedicated detail request fails or times out, marking it stale instead of deleting user-visible state. Persisted quota snapshots follow the same evidence-authority rule. (Web / Data consistency)
- After banked-reset consumption, reuse the existing one-shot quota refresh to verify recovery. Manager can then request early recovery of an exactly matched CPAMP-owned Codex quota cooldown while continuing to reject manual disables, pre-disabled credentials, and ambiguous ownership. (Web / Manager Server)
- Keep the flow event-driven: no provider polling, background reset-credit queue, periodic job, or new timer is added. (Web / Manager Server)
- Support saving and editing OpenAI-compatible providers without an API key, correctly representing them as empty `api-key-entries` or explicit keyless entries that retain CPA-supported per-entry settings such as proxy and weight. (Web / OpenAI compatibility)
- Keyless connectivity tests, model discovery, and health checks no longer send an empty `Authorization: Bearer` header. User-defined headers, per-entry proxy settings, and existing CPA `auth-index` routing remain intact; editing a real API key invalidates only the stale transient `auth-index` tied to the previous credential identity. (Web / Authentication)
- When keyed and keyless entries coexist, model discovery prefers a real API-key entry and falls back to a configured keyless entry only when no real key is available. (Web / Model discovery)
- When CPA cannot account for keyless traffic, CPAMP marks the usage data unavailable; mixed keyed/keyless providers are marked partial. Coverage-aware sorting and detail views preserve that distinction instead of interpreting missing accounting as zero traffic. (Web / Usage integrity)
- `Keys Count` now counts only real non-empty API keys, while keyless routes are labeled explicitly in health checks and provider details. (Web / Provider UI)

## Upgrade Notes

- No database migration or CPAMP configuration change is required.
- Existing OpenAI-compatible providers that use API keys retain their previous behavior. Keyless support is limited to OpenAI-compatible providers and does not extend to other provider families.
- Keyless requests do not receive a placeholder API key or empty Bearer authentication. Existing custom headers and per-entry proxy settings continue to apply.
- The Codex reset-state fix adds no periodic polling. Single-account manual refresh remains event-driven, and bulk/list refresh does not start a background reset-credit refresh queue.
- Manager-backed early recovery applies only when CPAMP can prove ownership of the exact cooldown. Deployments without Manager or without sufficient ownership evidence fail closed and retain partial-success semantics.
- The full Muse / Meta compatibility baseline remains **CPA v7.3.4+**; this release does not raise the minimum CPA compatibility baseline.
