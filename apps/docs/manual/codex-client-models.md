# Codex 客户端模型目录

模型目录页面展示 CPA 当前下发给 Codex 客户端的模型条目，并允许在本地覆写这些条目。它修改的是 CPA 下发的目录内容，不是 AI 提供商配置，也不是 Codex 客户端自身的配置。

打开 [模型目录 Demo](https://seakee.github.io/CPA-Manager-Plus/#/demo/codex-client-models) 可以查看虚构目录与覆写效果，不会连接真实 CPA。

页面入口需要当前 CPA 版本支持对应的能力标记。旧版本 CPA 不会显示该入口，直接访问会回到[配置中心](./configuration.md)。

## 最常用流程

1. 在列表中点击模型名称，条目会在原位展开，右侧留出编辑空间。
2. 需要以另一个模型为基准时，先在「继承源」里选好来源；没有单独覆写的字段都取自该模型。
3. 在常用字段里修改需要调整的项。
4. 选择「保存覆写」，改动写入本地覆写并对 Codex 客户端生效。

列表会显示每个模型的来源、下发状态、上下文窗口、默认推理级别和可见性。来源分五种：基础表示目录里有这个模型的条目，自动装配表示目录里没有它的条目、由服务端按默认模板装配，已覆写表示本地改过条目内字段，已删除表示条目被本地写成 null，未生效表示这条覆写对应的模型当前没有服务端。来源只说明条目的来历，字段取值的基准始终是服务端装配出来的条目。

页面顶部会显示当前目录的来源、修订号与覆写文件路径。

## 建立专属配置

服务端下发的列表是「它当前能提供的模型」逐个装配的结果：目录里有这个模型就用目录条目，没有就用默认模板加模型元数据装配一条。这些装配结果就是默认配置，页面顶部显示的目录与展开后每个字段的默认值都取自它们。

展开一个还没有本地覆写的条目会进入「建立专属配置」：

- slug 是客户端请求模型时使用的标识，因此不能修改。
- 保存后本地会新增一条只声明 slug 的覆写条目。
- 字段的基准就是客户端现在收到的配置：改到哪个字段，哪个字段才成为覆写。
- 客户端现在收到的取值都显示为默认值，不需要为了「保持现状」而逐个覆写。

不建立覆写也能照常使用这个模型，它仍会按装配结果下发。

## 列表与筛选

- 搜索框按 slug 或展示名过滤。
- 筛选按钮按来源分组统计，可以在全部、自动装配、已覆写、未生效、已删除和基础之间切换。
- 「下发」列标记该模型当前是否在客户端能看到的列表里，悬停可以看到提供它的服务端来源；显示「未下发」的条目通常是被本地写成了 null，或提供该模型的凭据暂时不可用。
- 右上角可以刷新目录、新增条目，或清空全部覆写。新增条目用来为某个 slug 写覆写：服务端能提供这个模型时，字段按它的装配结果给出默认值；还没有服务端时没有可对照的默认值，填写的取值都会作为本地覆写保存。
- 有覆写的条目右侧会出现移除覆写按钮，只影响这一条。

## 常用字段

常用字段按用途分组，最常用的项直接可见：

- 基本信息：展示名称、描述、可见性、优先级。
- 上下文与推理：上下文窗口、最大上下文窗口、最大输出 tokens、自动压缩阈值、支持的推理级别、默认推理级别、默认推理摘要、默认回复详略、支持详略控制。
- 能力开关：API 可用、并行工具调用、推理摘要、搜索工具、优先 WebSocket、使用 Responses Lite。
- 工具与模态：输入模态、补丁工具类型、Shell 类型、搜索工具类型、多智能体版本、多智能体推理强度。
- 提示词：基础提示词、模型消息，以及技能、应用与插件使用说明的开关。

其余字段收在展开区下方的「高级配置：其余字段」里，默认折叠。条目原始 JSON 收在「JSON 补丁」里，同样默认折叠；它是整体替换入口，改完要先「应用」写回表单或「还原」放弃修改，未应用时无法保存。

## 字段级来源

每个字段右上角都有一个来源标记，显示这个值当前是默认值、本地覆写，还是继承自另一个模型。

- 标记可以展开，用来把单个字段指定到别的继承源。
- 每个字段都可以单独恢复默认，不必撤销整个条目的改动；恢复后的字段停在默认值上，不会被条目的继承源重新接管。
- 只在某个字段需要特殊取值时，指定该字段的来源即可，其余字段仍跟随条目的继承源。
- 继承来的取值与该模型自身的默认值不同时，标记旁会多出一个「与默认值不同」的提示；同值继承对下发给客户端的内容没有影响，因此不加提示。

默认值是服务端装配出来的条目：目录里的模板加上模型元数据（上下文长度、推理级别、来源能力等）之后，客户端不写任何覆写时会收到的配置。覆写层叠在装配结果之上，所以每个字段都能覆写，包括那些过去会被规范化覆盖掉的字段。

模型的标识、在目录里的位置，以及它的上下文与推理配置（上下文窗口、token 预算与推理强度）永远由条目自身提供：来源供不到它们，指向它们的继承指令也会被拒绝。其余字段照旧跟随条目的继承源，需要让其中某个字段停在默认值上时，编辑器会在该路径写下「不继承」。

条目被其他覆写当作继承源时，编辑器标题旁会显示被引用次数。

## 提示词

基础提示词与模型消息里的指令模板通常内容一致，所以「基础提示词与指令模板一起覆写」默认开启，保存时同时写入两处。关掉开关后，两个字段分别显示、分别编辑。

两个字段来自不同模型时，合并框会提示来源不一致，选择任意一个来源即可让它们重新一致。

提示词默认折叠，展开前显示最多四行预览，折叠状态下不会占用过多高度。

## 继承的文件格式

页面上的「目录」是服务端为每个可服务模型装配出的默认条目，覆写层叠在它们之上，保存在本地覆写文件里，路径显示在页面顶部。每个条目以 slug 为键，继承写在 `$inherit` 字段中：

```json
{
  "my-fast-sol": {
    "$inherit": "gpt-5.6-sol",
    "slug": "my-fast-sol",
    "display_name": "My Fast Sol"
  },
  "my-sol-lite": {
    "$inherit": {
      "": "gpt-5.6-sol",
      "base_instructions": "gpt-5.6-terra",
      "model_messages.instructions_template": null
    },
    "slug": "my-sol-lite",
    "display_name": "My Sol Lite"
  },
  "gpt-5.6-terra": {
    "slug": "gpt-5.6-terra"
  }
}
```

- 条目可以只写 `slug`：这表示本地有一条条目，取值与装配结果完全一致，界面新建条目写出的就是它。
- `$inherit` 取字符串时表示整条条目继承该模型。
- `$inherit` 取对象时是「点号路径 → 来源 slug」的字段级映射，空字符串等价于整条继承。
- 路径取 `null` 时表示该路径不继承：取值回到条目自身，上级指令不再覆盖它，界面里的「恢复默认」写的就是它。
- 本地字段最后生效，可以覆盖继承来的值；在字段路径上写 `null` 表示删除该字段。
- slug、展示名称、描述、可见性、优先级，以及上下文与推理配置（context_window、max_context_window、max_tokens、auto_compact_token_limit、supported_reasoning_levels、default_reasoning_level、default_reasoning_summary、default_verbosity、support_verbosity）只由条目自身提供，不参与继承。

来源解析到的是那个模型的**下发条目**：它自己的覆写同样算数。如果一个官方模型当前没有任何来源在服务它，就用它的目录模板当来源，因此 `$inherit: "gpt-5.5"` 在没有 Codex 来源的机器上照样能写。

继承可以链式指向另一个覆写条目，也可以指向官方目录里的条目。

覆写写错了不会让模型消失：无法应用的那一条会在页面顶部报出来，该模型继续按装配结果下发。

## 覆写没有生效时

页面顶部会列出没有生效的覆写，并给出 slug、出问题的字段路径和原因。

- 单条条目出错时，其余条目仍然生效，出错的那一条退回服务端装配出的默认条目。
- 覆写文件整体无法解析时，页面会说明原因并继续使用上游目录。
- 通过页面保存会立即生效；直接修改覆写文件时，服务会监听该文件并自动重新读取。

## 配置边界

- 覆写只影响 CPA 下发给 Codex 客户端的目录，不改变 CPA 到上游的请求路由。
- 覆写条目不会随上游目录更新而消失，但继承来的字段会跟随来源条目一起更新。
- 目录会在刷新上游目录后重新套用本地覆写，因此不需要每次更新后手工重做。
