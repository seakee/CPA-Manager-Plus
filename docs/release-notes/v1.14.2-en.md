## Overview

v1.14.2 is a stability patch for v1.14.1 focused on CPA v8 configuration compatibility and the model-pricing/account-history failures exposed after Usage Maintenance archives raw history.

After CPA v8 moved client API keys to `access.api-keys`, the legacy read path could show an empty API Key list when Settings was opened for the first time. This release reads the effective v8 field while retaining compatibility with older configurations. For databases that already ran supported usage archive cleanup, model-price structural changes can now rebuild pricing when the retained monitoring projection proves the deleted history completely. If exact historical pricing for an individual account can no longer be recovered, account history no longer fails the whole request with HTTP 500: only that account's estimated cost becomes unavailable while trusted request, token, success/failure, seen-range, and recent-request metrics remain available.

## Highlights

### Fixes

- Fix client API keys appearing empty on initial Settings load or reload after CPA v8 moved them to `access.api-keys`; an explicitly present v8 field takes precedence while older layouts keep their compatibility fallback. (Web / CPA compatibility)
- Fix model-price structural sync becoming permanently blocked after supported Usage Maintenance archive cleanup; pricing rebuilds can reuse retained monitoring history when deleted coverage is fully provable, while genuinely incomplete legacy history remains fail-closed. (Manager Server)
- Fix account-history requests failing completely when historical pricing cannot be reconstructed exactly; only affected accounts now return `total_cost: null` and render `-`, while healthy accounts keep exact cost and the remaining trusted historical metrics stay available. (Manager Server / Web)

### CI

- Add bounded retries for idempotent GitHub API reads and PATCH updates in update-index publication, reducing the chance that transient transport failures leave GitHub Latest or the update channel on an older version; non-idempotent POST Git-object writes remain non-retryable. (Release)

## Upgrade Notes

- No database migration or configuration change is required.
- Instances that already ran supported Usage Maintenance cleanup do not need to restore deleted raw usage; only history that can be proven exactly from the retained projection participates in pricing rebuilds.
- Accounts whose historical prices cannot be recovered exactly show `-` for cost rather than a synthesized estimate; other trusted history metrics remain available.
- The full Muse / Meta compatibility baseline remains **CPA v7.3.4+**; this release does not raise the minimum CPA compatibility baseline.
