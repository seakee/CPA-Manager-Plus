## Overview

This is the third beta of v1.12.0, focused on consistent Accounts quota lifecycles, resilient SQLite access during compatible usage downloads, and clearer monitoring, log, and system navigation. Quota usage now remains correct across early or scheduled resets, deep-link loading, and detail-drawer reopening; slow compatible downloads no longer retain SQLite readers for their full lifetime; and the frontend standardizes cost precision while refining log, plugin, and system entry points.

## Highlights

### Features

- Display USD costs with exactly three fractional digits across Monitoring, Dashboard, Usage Analytics, and Accounts while leaving stored values and calculations unchanged (`web/usage`).
- Keep Logs visible by default, move request-log control into visual configuration, and remove the hidden Dashboard unlock gesture while preserving direct log access (`web/logs`, `web/config`).
- Hide plugin-management navigation when plugins are explicitly disabled while preserving compatibility when older environments omit capability fields (`web/plugins`).
- Rename server-version and main-program repository labels to core terminology and point the tutorial action to the current CPAMP online documentation (`web/system`).

### Fixes

- Confirm scheduled or early quota rollovers only from reliable exact or derived boundaries, preventing provisional zero-use or unknown evidence from incorrectly splitting an active cycle (`manager-server/quota`).
- Preserve normalized current and previous quota-cycle usage after activation, scheduled rollover, or early reset; labels use scheduled bounds while aggregation retains observed query intervals (`web/accounts`, `manager-server/quota`).
- Reload quota usage after manual refresh, reopening the same credential drawer, or asynchronously resolving a deep-linked credential, avoiding empty or stale details (`web/accounts`).

### Performance

- Load compatible usage details in batches after releasing SQLite readers, allowing WAL checkpoints to progress during slow downloads while preserving response shape, ordering, and the JSONL export path (`manager-server/usage`).
- Add a non-destructive SQLite index for quota-cycle evidence lookups so lifecycle normalization remains bounded as snapshot history grows (`manager-server/sqlite`).

### Chore

- Exclude `apps/web` from GitHub Linguist primary-language detection so repository metadata represents the Go application without changing builds or runtime behavior (`repo`).

## Upgrade Notes

- This is a prerelease. Stable Docker tags and `latest` are not updated; use the explicit `v1.12.0-beta3` image or release assets.
- When the configured limit for `GET /v0/management/usage` exceeds 50,000 rows, the endpoint returns the latest 50,000; `/v0/management/usage/export` continues to honor the configured limit.
- Manager Server automatically adds a non-destructive quota-cycle lookup index; no manual migration or data rewrite is required.
- Quota lifecycle persistence fixes apply to deployments using Manager Server storage. Existing CPA Panel direct-mode capability boundaries remain unchanged.
