## Overview

v1.14.3 is a stability patch for v1.14.2 and stays within the frozen 1.x maintenance boundary. It addresses three confirmed compatibility and reliability issues: Usage Maintenance archive cleanup repeatedly stopping under transient SQLite writer contention, CPA v8 configuration-layout changes causing incorrect visual-config reads or writes, and missing Safari / iOS-compatible site icons.

Archive cleanup now distinguishes transient SQLite `BUSY` / `LOCKED` contention from genuine derived-state failures. A safely committed state that already covers the cleanup target is no longer poisoned by transient writer contention, while rebuilds, backfills, genuine failures, and insufficient coverage remain fail-closed. The visual configuration editor now follows CPA v8 canonical paths, historical aliases, YAML merge / alias semantics, and runtime capability boundaries while preserving legacy configuration behavior. The web panel also adds `favicon.ico` and `apple-touch-icon.png`: Full Mode serves conventional root resources, while the lightweight panel remains a single-file distribution and uses embedded fallbacks on current Safari / iOS when the root resources are not CPAMP assets.

## Highlights

### Fixes

- Fix Usage Maintenance archive cleanup repeatedly stopping when transient SQLite `BUSY` / `LOCKED` contention incorrectly turns an already safe derived state into a failure; genuine failures, rebuild/backfill states, and insufficient coverage still block raw deletion. (Manager Server)
- Complete CPA v8 visual YAML compatibility by reading canonical paths, historical v8 aliases, and legacy paths with CPA-compatible presence and precedence semantics, and by writing canonical paths only for actual v8 layouts. Legacy-only configurations keep their existing behavior. (Web / CPA compatibility)
- Cover YAML aliases, `<<` merge keys, partial mixed layouts, Management Key preserve/clear behavior, Commercial Mode persistence, and the CPA-runtime capability boundary for Codex `identity-confuse`. (Web / CPA compatibility)
- Add a multi-size `favicon.ico` and an opaque 180×180 Apple Touch Icon. Full Mode serves fixed root resources through Manager Server with GET / HEAD-only handling. (Web / Manager Server)
- Keep lightweight `management.html` single-file: current Safari / iOS switches to byte-identical embedded Data URL icons when the conventional root response is not identified as a CPAMP asset, so CPA does not need to download companion icon files. (Web / CPA lightweight panel)

### Docs / CI

- Update Chinese and English lightweight-panel, reverse-proxy, FAQ, and update documentation with same-domain routing guidance for `/favicon.ico` and `/apple-touch-icon.png`.
- Add release and PR integrity checks for the web icon assets so Vite / Go copies and the final single-file fallbacks stay byte-identical.

## Upgrade Notes

- No database migration or CPAMP configuration change is required.
- Instances using Usage Maintenance do not need to change archive settings; cleanup still requires target-scoped committed coverage from the current schema / revision.
- CPA v8 users can continue using the existing visual configuration page. This release adds no new 1.x configuration surface; it only fixes mappings for settings that already exist.
- Custom same-domain reverse proxies that need conventional root icons for older Safari / iOS should route `/favicon.ico` and `/apple-touch-icon.png` to CPAMP Manager Server. Current Safari / iOS can still use the embedded lightweight-panel fallback.
- Safari 18 and earlier do not reliably support Data URL icons, so the CPA lightweight panel alone does not guarantee a custom Home Screen icon on those legacy versions. Full Mode is not affected.
- The full Muse / Meta compatibility baseline remains **CPA v7.3.4+**; this release does not raise the minimum CPA compatibility baseline.
