## Overview

v1.14.2 是 v1.14.1 的稳定性补丁版本，集中修复 CPA v8 配置兼容和 Usage Maintenance 清理历史数据后暴露出的模型定价、账号历史查询问题。

CPA v8 将客户端 API Key 移到 `access.api-keys` 后，旧读取路径会让设置页在首次打开时显示空列表；本版本按 v8 有效字段读取，同时保留旧配置兼容。对于已经执行过受支持用量归档清理的数据库，模型价格结构变更现在可以在保留的 monitoring projection 足够完整时重建定价；若个别账号的历史定价已经无法精确恢复，账号历史不再整体返回 500，而是只将该账号的预估费用降级为不可用，同时保留请求数、Token、成功率、时间范围和最近请求等可信指标。

## Highlights

### Fixes

- 修复 CPA v8 使用 `access.api-keys` 后，设置页首次打开或重新加载时客户端 API Key 列表为空的问题；显式存在的 v8 字段优先，旧配置继续使用兼容回退。（Web / CPA compatibility）
- 修复执行受支持的 Usage Maintenance 归档清理后，模型价格结构同步可能被永久阻止的问题；当已删除历史可由保留的 monitoring projection 完整证明时，定价重建会复用保留历史，真正不完整的旧数据仍保持 fail-closed。（Manager Server）
- 修复历史定价无法完整恢复时账号历史接口整体失败的问题；现在只对受影响账号返回 `total_cost: null`，前端显示为 `-`，同批次健康账号继续保留精确费用，其余永久历史指标仍可用。（Manager Server / Web）

### CI

- 发布链路的 update-index GitHub API 读取与 PATCH 更新增加有限重试，降低瞬时网络错误导致 GitHub Latest / 更新通道停留在旧版本的概率；非幂等 POST Git 对象写入仍不自动重试。（Release）

## Upgrade Notes

- 无需数据库迁移或配置变更。
- 已执行受支持 Usage Maintenance 清理的实例无需恢复已删除原始用量；只有能由现有保留 projection 精确证明的历史才会参与定价重建。
- 对无法精确恢复历史价格的账号，费用会显示为 `-`，不会合成或猜测金额；其他可信历史指标继续显示。
- 完整 Muse / Meta 功能的 CPA 基线继续为 **v7.3.4+**；本版本没有提高最低兼容基线。
