## Overview

v1.14.8 is a 1.x maintenance release after v1.14.7. It includes four merged frontend fixes: background-refresh data continuity (#1001), provider-aware source attribution in request monitoring (#1014), quota-window presentation (#1020), and xAI OAuth subscription-plan and observed-quota handling (#1006).

This release contains no v2 architecture work and does not change the Manager Server, CPA management APIs, database schema, credential format, or configuration format. There are no new user settings or migration steps.

## Fixes

- **Background-refresh continuity (#1001):** Keep loaded credential history, quota usage, Usage Analytics data, and model-price rows visible while refreshing within the same connection and data scope, including temporary request failures. Avoid flashing, blank content, or false empty states.
- Credential replacement invalidates historical and quota-usage evidence belonging to the previous credential identity without discarding unaffected rows. Rolling-range day changes and changed filters still invalidate out-of-scope data.
- **Request-monitoring source attribution (#1014, fixes #1013):** Disambiguate shared API keys and host ordinals across providers using the event provider where available. Preserve configured upstream labels; fall back to an unattributed source rather than guessing when the provider is missing or candidates remain ambiguous. Raw API keys are not displayed.
- **Quota-window presentation (#1020):** Show up to five principal Antigravity quota windows in both cards and table rows, including a separate Gemini 4 Argon group. Distinguish confirmed empty model usage from unknown, stale, partial, or unavailable quota data.
- **xAI OAuth subscriptions (#1006, fixes #1005):** When a CPA auth file lacks plan information, resolve the subscription in the background through CPA's existing `api-call` endpoint. Display a confirmed SuperGrok Heavy plan where available, and continue showing observed quota even when subscription status cannot be confirmed.
- Keep xAI quota observations separate from account-health entitlement decisions: stale plan evidence cannot establish availability or cross connection/credential boundaries. Subscription lookups are deduplicated through a low-priority serial lane after quota refresh; no periodic polling is added.

## Upgrade Notes

- **Upgrade from v1.14.7 and restart normally.** No database migration, configuration rewrite, or credential recreation is needed; `migration_required` remains `false`.
- The subscription lookup in #1006 uses the existing CPA `api-call` capability and upstream subscription endpoints. If these are unavailable, the plan can remain unknown while observed quota stays visible; old plan labels alone do not establish availability.
- The retained snapshots in #1001 are scoped to the same connection and credential/filter identity. Scope changes still invalidate previous evidence.
- The minimum CPA baseline for full Muse / Meta functionality remains **v7.3.4+**; this release does not raise it.
- The existing v1.14.7 offline-maintenance guidance for the latency-analytics covering index on populated databases still applies. This release introduces no further indexes or maintenance commands.
