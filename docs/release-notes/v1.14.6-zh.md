## Overview

v1.14.6 是 v1.14.5 之后的 1.x 维护补丁版本，仅收录三个已合并并通过 CI 的问题修复：Codex 工作区预算限制的识别与展示（#935 / #938）、归档清理前的历史监控投影完整性保护（#939 / #945），以及未知提供商在严格 CPA v2 计量证据下的缓存 Token 重复计算（#941 / #946）。

本版本不增加新功能、后台轮询或定时器，也不改变 CPA 管理 API、凭证权限或数据库 Schema。

## Highlights

### Fixes

- **Codex 工作区消费预算（#935 / #938）**：正确识别结构化 `spend_control.individual_limit`，同时兼容旧版标量数据与浏览器中已持久化的额度缓存。保留预算总额、已用、剩余额度、单位、周期及重置证据；已触发的消费限制仍显示为受限，不再被普通 5 小时或周额度余额掩盖。
- 对 `0 / 0` 等零预算场景显示具体的 workspace budget 原因，不以“已用 100%”代替解释。仅在消费限制证据完整且没有其他冲突限制时，建议检查工作区预算；同时存在其他限制时保留额度刷新建议。没有新增后台额度探测或轮询。
- **归档清理数据保护（#939 / #945）**：清理原始请求事件前，按批次验证保留的 Monitoring 投影行确实存在且时间戳匹配。缺失或不匹配时，仅在同一 SQLite 事务内从仍存在的原始数据补齐并复核；无法证明安全交接则回滚并停止删除。
- 中断后恢复清理时还会检查本次任务已删除事件的保留投影，避免在已受损的清理状态下继续删除。该修复防止未来清理造成同类缺口，**不会虚构或自动恢复升级前已永久丢失的历史原始事件**。
- **CPA v2 缓存计量（#941 / #946）**：对原本无法归类的事件，只有当 CPA v2 的 `accounting_version=2` 与 `token_breakdown.schema_version=2` 提供完整、内部一致的输入、缓存、输出、推理及总量证据时，才采用规范化缓存语义，避免将缓存读取 Token 再计入输入。
- 保留既有显式规则及已知 Provider / Executor / Model 的优先级；证据缺失、歧义、版本未知或不一致时继续采用原回退逻辑。标准 JSONL 导入导出会区分上游显式计量模式与 CPAMP 派生模式，不会将派生结论伪装成上游原始声明。
- 对符合条件的历史在线 `usage_events` 自动执行缓存计量语义修正，并通过现有迁移链重建相关聚合与费用结果，不需要手动编辑 SQLite 或执行离线清理命令。

## Upgrade Notes

- **正常升级并重启即可**。没有数据库 Schema 迁移或配置格式变更，但会对符合条件的历史记录运行自动计量语义修正，并重建相关用量 / 费用汇总；升级后统计值可能相应变化。
- 建议在升级前保留一致的数据库及归档备份。若需要回退到升级前的精确历史计量状态，应恢复同一时间点的数据库与归档备份，而不是手工逆向修改派生计量字段。
- 新的严格缓存计量分支只在 CPA v2 规范证据完整时生效；其他事件沿用原有兼容规则。完整 Muse / Meta 功能的 CPA 最低兼容基线仍为 **v7.3.4+**。
- 归档清理的新增验证可能增加少量批次处理开销；不能验证保留投影时将优先停止清理，保护原始数据。
- 无需新增后台轮询、定时器或手动数据修复步骤。
